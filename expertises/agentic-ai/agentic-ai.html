The moment it becomes a real subject

Recognize one of these dated events—or this is not the engagement yet.

The buying trigger is not “we should do agentic AI.” It is a production decision with an owner, a deadline and a failure boundary.

01

A demo must become a service

The agent can now call real tools or change real state, but nobody can enumerate its effective authority.

02

Security asks what the agent can reach

The answer is distributed across prompts, connector configuration, application code, credentials and human convention.

03

An incident cannot be replayed

Logs show calls, but not the full decision trajectory: objective, retrieved context, policy decision, tool side effect and human intervention.

04

A model or tool must change

No representative regression set exists to decide whether the new system is safe enough to promote.

Consequences

Three shortcuts fail for different reasons.

The issue is not that agents are “unpredictable” in the abstract. It is that authority, memory and evaluation can remain implicit until a consequential action forces them into the open.

Authority

“Do not do X” is not an authorization system.

The logic before the tools

Build the production control boundary around the agent—not more confidence into the prompt.

The Agent Production Control Loop™ is a delivery model: Authority → Context → State → Tool / Side Effect → Evaluation → Observation → Human Decision → Rollback. Each boundary is made inspectable before it is automated further.

Acceptance outcomes

Three things the operating team should be able to do at handover.

Explain and constrain authority

For each agent path, state what can be read, written, called, delegated, denied, escalated and revoked.

Evaluate a change before promotion

Run representative and adversarial cases against a pinned system snapshot and decide against explicit thresholds.

Operate the control loop without hidden ownership

Use traces, review queues, runbooks and rollback criteria without relying on undocumented consultant knowledge.

Process

Four phases, each ending in an artifact and a decision.

Map

Inventory objectives, consequential actions, tools, credentials, context sources, state and failure modes.

Exit: authority + failure map

Bound

Turn tools, identities, memory writes and external side effects into declared runtime contracts.

Exit: governed agent registry

Evaluate

Build representative tasks, adversarial cases, graders and promotion thresholds tied to intended use.

Exit: evaluation harness + release gate

Handover

Your team runs the loop without the consultant, including review, denial, rollback and incident reconstruction.

Exit: accepted runbook + tested stop path

The structure deliberately separates governance, context mapping, measurement and risk action. NIST AI RMF organizes AI risk management into four functions—Govern, Map, Measure and Manage; it explicitly notes that they are not an ordered checklist.

Commitments

The guarantee is on the product of work and acceptance process—not on an authority’s decision or a model’s future behavior.

Scope before billing

Scope, exclusions, dependencies and acceptance criteria are written before the first billed delivery day.

Acceptance before “done”

A deliverable that misses its agreed acceptance criteria is revised against those criteria; the definition is set before production.

Reversible handover

Code, schemas, evaluation assets, decisions and runbooks are transferred under the agreed contract, without inventing proprietary lock-in as a dependency.

Confidentiality boundary

Each data-bearing work item is classified before use: authorized, anonymized, synthetic or prohibited.

Human decision boundary

Every consequential case states where automation stops and which client role owns approval or refusal.

Tool-neutral control model

Objectives, evidence and acceptance criteria are separated from any single model or vendor wherever the architecture permits.

Not guaranteed: zero incidents, universal prompt-injection prevention, foundation-model accuracy, regulatory approval, revenue or a predetermined architecture.

Questions

Questions that materially change architecture, price or responsibility.

Do we need to replace our agent framework?Usually no. First test whether your current stack can expose the required identity, authority, state, evaluation and trace hooks. Replace only when a critical control cannot be implemented without it.
Our data cannot leave our environment. Is that a blocker?No by default. The engagement can be performed in your infrastructure and accounts. Data movement becomes an explicit design constraint, not a hidden assumption.
Who decides production promotion?Your accountable role. The mandate can define the evidence and threshold, but it does not usurp organizational accountability.
Can we start smaller than three months?Yes for qualification or a bounded diagnostic. If the need is only to map authority, risks and evidence, do not buy an implementation mandate.
Do you build with MCP?Where it fits. MCP is treated as an integration surface whose server, tool, identity, credential and side-effect boundaries need explicit governance—not as the product itself.
